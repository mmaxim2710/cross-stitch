# Вышивка крестиком

PWA, чтобы вышивать по схеме с телефона: открыть схему, подсветить нужный цвет,
отмечать выполненные клетки и не терять прогресс. Приложение на одного
человека — без аккаунтов и регистрации, прогресс хранится в IndexedDB
устройства и работает офлайн.

Схемы Pattern Maker v4 (`.xsd`) приложение разбирает само, прямо в браузере;
тот же формат читает и конвертер `tools/xsd2json.py`, если удобнее подготовить
JSON заранее. Внутри схема — палитра плюс один байт на клетку.

Что умеет: просмотр схемы с паном, зумом, линейками и символами; палитра с
приглушением невыбранных цветов и обводкой выбранного цвета; отметка клеток
тапом и свайпом с подтверждением и undo/redo; синхронизация прогресса через
Cloudflare Worker + D1 с трёхсторонним слиянием; бэкап в файл; wake lock;
тёмная тема.

## Как запустить

```sh
cd app
npm install
npm run dev
```

Открывать `http://localhost:5173`. Порт и хост зафиксированы в `vite.config.ts`:
сервер слушает все интерфейсы, а не только `localhost` — иначе на Windows он
садится на `::1`, и часть браузеров получает `ERR_CONNECTION_REFUSED`.

Заодно это даёт адрес для телефона — vite печатает его при старте
(`Network: http://192.168.x.x:5173/`). Телефон должен быть в той же сети. По
HTTP схема смотрится нормально, но установка на домашний экран и офлайн-режим
требуют HTTPS, так что PWA целиком проверяется только на Pages.

Dev-сервер отдаёт всё, что лежит в `data/*.json`, по адресу `/patterns/`.

```sh
npm run build      # сборка в app/dist, без схем
npm run icons      # перегенерировать иконки PWA
npm run check:xsd  # сверить TS-парсер .xsd с Python-версией
```

`check:xsd` проверяет, что оба парсера дают одинаковый результат на
`schemas_example/night.xsd` и `data/night.json`; ни того, ни другого нет в
репозитории, так что сначала нужно положить файл и прогнать `xsd2json.py`.

## Схемы и приватность

Схемы — чужая интеллектуальная собственность, а сайт GitHub Pages публичен
всегда, независимо от видимости репозитория. Поэтому `data/` и
`schemas_example/` лежат в `.gitignore` и в сборку не попадают: свежий клон
запускается пустым и предлагает открыть файл.

На телефон схема добавляется через «Схемы → Открыть схему»: `.xsd` или готовый
`.json` разбирается в браузере и остаётся в IndexedDB. Если настроена
синхронизация, схема заодно уезжает в D1 — так её видно на других устройствах и
она переживёт переустановку. Собрать сборку со вшитыми схемами — для локального
использования — можно так:

```sh
VITE_EMBED_PATTERNS=1 npm run build
```

## Код на входе

Приложение открывается клавиатурой на четыре цифры; код зашит в
`app/src/ui/lock.ts`. Это не защита: страница на Pages публична, и код лежит в
бандле — он только закрывает дверь тому, кто случайно набрёл на адрес. Введённый
код запоминается в `localStorage`, так что спрашивают его один раз на устройство;
если поменять код в исходнике, все устройства попросят его заново.

## Управление

| | Просмотр | Отметка |
|---|---|---|
| Перетаскивание | панорамирование | выделение клеток |
| Тап | выбрать цвет клетки | выделить одну клетку |
| Двойной тап | вписать схему в экран | — |
| Два пальца | зум | зум |

Режимы разделены намеренно: иначе жест панорамирования конфликтует со
свайп-выделением и приводит к случайным отметкам.

В режиме отметки жест ничего не записывает — он только набирает выделение,
подсвеченное синей заливкой с обводкой. Что с ним сделать, решают кнопки на
панели снизу: **✓** отмечает выделенное выполненным, **✗** снимает отметку,
«Сбросить» отпускает выделение. Так случайный свайп по схеме больше не стоит
прогресса. Направление свайпа задаёт первая клетка: начали с невыделенной —
весь свайп выделяет, и наоборот. Одна операция undo — это одно подтверждение
целиком.

Выполненные клетки закрашиваются ровным серым: пока они оставались своего цвета,
взгляд не отличал сделанное от несделанного. Выбранный в палитре цвет, наоборот,
обводится по контуру области — так видно, куда класть следующий стежок.

## Синхронизация

Прогресс всегда пишется в IndexedDB и только потом уезжает на сервер, поэтому
неудачная синхронизация ничего не стоит. Сервер — Cloudflare Worker с базой D1;
он хранит маску выполненных клеток и сами схемы.

Точка в шапке показывает состояние: серая — не настроено, зелёная —
синхронизировано, жёлтая — есть локальные изменения, синяя — идёт обмен,
красная — ошибка. Тап по ней открывает настройки.

### Развернуть свой

```sh
cd worker
npm install
npx wrangler login
npx wrangler d1 create cross-stitch    # id из вывода вписать в wrangler.toml
npm run schema                          # создать таблицы
npx wrangler secret put AUTH_TOKEN      # придумать токен
npm run deploy
```

Адрес вида `https://cross-stitch.<логин>.workers.dev` и токен вводятся в
приложении один раз: точка в шапке → «Адрес воркера» и «Токен» → «Проверить и
сохранить». Они лежат в `localStorage` устройства.

Бесплатного плана хватает с колоссальным запасом: 5 млн чтений и 100 тыс.
записей в день против нескольких записей в минуту от одного человека.

Локально:

```sh
echo AUTH_TOKEN=test-token > worker/.dev.vars
npm run schema:local
npm run dev
```

### Как разрешаются конфликты

У маски есть версия. `PUT` присылает версию, от которой отталкивался клиент;
если на сервере уже новее, приходит `409` вместе с текущим состоянием.
Клиент сливает маски трёхсторонним слиянием — клетки, изменённые локально,
побеждают, остальные берутся с сервера — и повторяет запрос:

```ts
const changed = local ^ base;
const merged = (local & changed) | (server & ~changed);
```

Простой last-write-wins потерял бы всё, что отмечено офлайн.

### Бэкап

«Настройки → Сохранить бэкап в файл» выгружает схемы и прогресс одним JSON.
Это запасной вариант на случай, когда недоступны и устройство, и Cloudflare:
Safari выселяет IndexedDB после семи дней без визитов (для приложения с
домашнего экрана правило не действует, но выселение под нехваткой места
возможно всегда).

## Деплой

`.github/workflows/pages.yml` собирает `app/` и публикует на GitHub Pages при
пуше в `main`. В настройках репозитория нужно выбрать Pages → Source → GitHub
Actions.
